### Где каких позиций не хватает [Ф]

## 5. Предложение новых цен (черновик Claude, ждёт решения владельца) [О]

**Как считалось.** Для каждой позиции взята медиана цен **прачечных** из раздела 3 (химчистки не учитывались) и добавлено около 10–15%, округление до 10 или 50 грн. Где у позиции 1–2 рыночные точки или их нет, это помечено. Себестоимость (химия, вода, электричество, время сушки, зарплаты) **неизвестна [?]**: прайс рыночный, не затратный. После 2–4 недель пилота его нужно сверить с реальной себестоимостью.

### 5.1 Розница и опт: что предлагаю

- **Розница = поштучно.** Каждая вещь осматривается, фотографируется и стирается отдельно от чужих вещей. Это и есть премиальный сервис, и поштучная цена его честно отражает. Клиент заранее знает сумму в Mini App.
- **Опт (B2B) = за кг**, от 10 кг или 1000 грн, как сейчас. Цены B2B на уровне рынка, менять не предлагаю.
- **«Прання по кг» для жителей не вводим на старте.** Такая услуга обычно смешивает вещи в одну загрузку без поштучного осмотра, а это спорит с позиционированием и с правилами приёма (п. 27 Правил № 614: огляд у присутності споживача). Вернуться к ней после пилота, если жители будут просить «просто постирать пакет».
- **Рушники** для розницы поштучно, для B2B за кг.

**Проблема [Ф].** Цены записаны в четырёх местах: `services.js` (Mini App и API), `PRICE_LIST` и шесть текстовых меню в боте, HTML сайта. Синхронизация ручная, в августе расхождения находили трижды.

**Предлагаемая схема [О]**

1. **Один файл** `mini/catalog/prices.json` (в репозитории `mini`, рядом с API). В нём все позиции: `id`, `section`, `name`, `price`, `unit` (`шт` / `кг` / `м²` / `пара` / `завантаження`), `price_from` (true там, где цена «від»), `aliases` (слова для распознавания в боте), плюс блоки `b2b`, `delivery`, `express`, `club`, `note`.
2. **API** читает этот файл при старте и отдаёт `GET /api/prices` (публично, без персональных данных). Расчёт суммы заказа остаётся на сервере, как сейчас.
3. **Mini App** берёт каталог из `GET /api/prices`. `services.js` превращается в запасную копию, которую генерирует скрипт из JSON.
4. **Бот** при старте и раз в час запрашивает `GET /api/prices`, строит `PRICE_LIST`, алиасы и тексты меню «Прайс» из ответа. Если API недоступен, работает со встроенной копией последней версии.
5. **Сайт** рендерит модалки прайса из `GET /api/prices` небольшим скриптом. В HTML остаются статичные цифры как запасной вариант и для SEO.
6. **Проверка:** скрипт `check_prices.py` сравнивает JSON с запасными копиями и падает, если есть расхождение (запускать перед каждым PR).

**Сравнение вариантов**

| Вариант | Стоимость | Сложность | Риски | Польза |
|---|---|---|---|---|
| А. JSON в `mini` + `GET /api/prices` (рекомендую) | только работа над кодом | средняя: 3 PR (API, бот, сайт) | если API спит, бот и сайт берут запасную копию | правка цены в одном файле через PR, история изменений в git |
| Б. Лист «Прайс» в Google Sheet | 0 | средняя | опечатка в таблице сразу ломает суммы; таблица уже медленная; правки без истории | владелец правит без GitHub |
| В. Оставить копии + проверочный скрипт | 0 | низкая | правка всё равно в 4 местах | ловит расхождения, но не убирает их |

**Порядок работ (каждый шаг отдельным PR, после согласования)**
1. `prices.json` + `GET /api/prices` в `mini`, `services.js` генерируется из JSON. Проверка: суммы заказа в Mini App не изменились.
2. Бот читает цены из API. Проверка: «Прайс» в боте показывает те же цифры, текстовый заказ «2 сорочки» считается 500 грн.
3. Сайт рендерит прайс из API. Проверка: модалки совпадают с Mini App.

**Как проверить после внедрения:** `curl https://mini-mrip.onrender.com/api/prices` возвращает JSON; изменить одну цену в JSON, смержить, убедиться, что через 1 час она видна в боте, Mini App и на сайте. Откат: кнопка Revert в GitHub или Rollback в Render.
